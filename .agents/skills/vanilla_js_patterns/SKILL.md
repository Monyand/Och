# Архітектурні стандарти Vanilla JS

При роботі над HTML-файлами та написанні JavaScript коду в цьому проєкті, я завжди буду дотримуватися наступних правил:

## 1. Управління станом (State Management)
- **НЕ** зчитувати стан безпосередньо з DOM-елементів (наприклад, перевіряючи наявність CSS-класів).
- Використовувати глобальний об'єкт стану (наприклад, `const appState = { ... }`) для зберігання даних застосунку.
- Всі зміни інтерфейсу мають відбуватися як реакція на зміну цього стану.

## 2. Безпечне оновлення DOM
- При генерації HTML-розмітки через шаблонні рядки (template literals) **завжди** екранувати дані, що вводяться користувачем.
- Використовувати функцію `escapeHtml()` (або подібну) для запобігання XSS-вразливостей.

## 3. Делегування подій (Event Delegation)
- Де це можливо та доцільно, використовувати делегування подій для динамічно створених елементів, замість того, щоб вішати сотні `onclick` чи додавати EventListener на кожен елемент.
- Додавати один обробник подій на батьківський контейнер та перевіряти `event.target`. *(Примітка: якщо в існуючому коді вже активно використовуються інлайн-обробники `onclick`, то підтримувати консистентність, але при рефакторингу віддавати перевагу делегуванню).*

## 4. Розділення логіки (Separation of Concerns)
- Чітко розділяти функції обробки даних (наприклад, парсинг Excel/Word) та функції відображення інтерфейсу (рендеринг).
- Логічні функції повинні повертати підготовлені дані, які потім передаються у функції рендерингу (наприклад, `renderRopList(data)`).

## 5. Структура коду (Script Organization)
- Дотримуватися чіткого порядку блоків у тегу `<script>`:
  1. Глобальні змінні та Об'єкт стану
  2. Допоміжні утиліти (Helpers, форматування дат, escapeHtml)
  3. Логіка обробки даних (Core Business Logic)
  4. Функції оновлення інтерфейсу (UI Rendering)
  5. Ініціалізація та глобальні слухачі подій (Event Listeners)
