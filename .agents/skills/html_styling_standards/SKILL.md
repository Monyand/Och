# UI/UX та Стилізація (Tailwind CSS)

При розробці інтерфейсу в цьому проєкті, я завжди буду дотримуватися наступних правил дизайну та верстки:

## 1. Преміальний та Сучасний Дизайн (Aesthetics First)
- **Уникати "базових" кольорів:** Не використовувати прості кольори (наприклад, просто `bg-red-500` або `bg-blue-500` без контексту палітри). Використовувати гармонійні відтінки (наприклад, з палітри `slate`, `indigo`, `emerald` тощо).
- **Мікро-анімації:** Додавати плавні переходи для інтерактивних елементів (кнопки, посилання, картки). Обов'язково використовувати класи `transition-colors`, `transition-all`, `duration-200`, `ease-in-out`.
- **Ефекти:** Використовувати легкі тіні (`shadow-sm`, `shadow-md`), заокруглення (`rounded-md`, `rounded-xl`) та ефект скла (Glassmorphism, `backdrop-blur`) де це доречно для створення сучасного вигляду.

## 2. Робота з Tailwind CSS
- **Темна тема:** Завжди враховувати підтримку темної теми. Використовувати префікс `dark:` для всіх кольорів (наприклад, `bg-white dark:bg-slate-800 text-slate-900 dark:text-white`).
- **Адаптивність (Responsive Design):** Інтерфейс має добре виглядати на різних екранах. Використовувати префікси `sm:`, `md:`, `lg:` для адаптації сітки та відступів.
- **Уніфікація класів:** Не створювати "кашу" з класів. Завжди групувати пов'язані класи (наприклад, спочатку layout/flex, потім spacing (p/m), потім кольори, потім типографіка, потім ефекти/анімації).

## 3. Семантичний HTML та Доступність (A11y)
- Використовувати правильні HTML5 теги (`<header>`, `<main>`, `<section>`, `<footer>`, `<nav>`, `<article>`) замість суцільних `<div>`.
- Для інтерактивних елементів використовувати `<button>`, а не `<div>` чи `<span>` з подією кліку.
- Всі кнопки з іконками повинні мати атрибут `title` або `aria-label` для пояснення їх дії.

## 4. Консистентність компонентів
- При створенні нових елементів (наприклад, кнопок чи карток), вони повинні візуально відповідати вже існуючим в проєкті (ті ж самі радіуси заокруглення, стилі границь, поведінка при наведенні `hover:`).
- Зберігати єдиний рівень контрастності для тексту (особливо в темній темі, уникати занадто яскравого або занадто тьмяного тексту).

## 5. Обов'язкова Типографіка (Inter & JetBrains Mono)
- **Головний шрифт інтерфейсу:** Завжди використовувати **Inter** (`font-family: 'Inter', sans-serif;` з Google Fonts) для всіх додатків.
- **Моноширинний шрифт:** Для числових кодів, індексів БК, назв файлів, логів та терміналів використовувати **JetBrains Mono** (`font-family: 'JetBrains Mono', monospace;`).
- Заборонено використовувати випадкові системні шрифти (Times, Arial, Georgia, базовий sans-serif без підключеного Inter).

## 6. Стійкість верстки до масштабування (Zoom Stability)
- **Багаторівневі тулбари:** Розбивати панелі фільтрів та статистики на 2 окремі стабільні рядки (`Row 1: пошук + випадаючі списки`, `Row 2: статистика + скидання`), щоб при зумі (125%, 150%, 175%) елементи не виштовхували один одного і не ламали сітку.
- **Орієнтація випадаючих меню (Popovers):** Кнопки меню в правій частині екрана повинні мати класи випадаючого контейнера `right-0` (відкриття наліво), щоб вони не обрізались правим краєм екрана.
- **Z-Index для модалок:** Модальні вікна повинні мати `z-[200]` або `z-[210]`, щоб перекривати всі фіксовані панелі та індикатори.

## 7. Автономна офлайн-архітектура (100% Offline Ready)
- Кожен додаток повинен працювати як повністю автономний `.html` файл.
- Зовнішні бібліотеки (Tailwind, Lucide, XLSX) повинні мати механізм локального або безпечного завантаження з резервним підключенням.
