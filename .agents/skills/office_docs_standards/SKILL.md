# Стандарти роботи з Excel та Word (HTML + Python)

## 1. Excel у браузері (`v8/xlsx.js` + `v8/jszip.min.js`)

### Штабний стиль та верстка таблиці
- Шрифт: **`Calibri` 10pt** (`sz: 10`), заголовок аркуша **`12pt bold`**, підзаголовок **`9.5pt` `#4D5562`**, основний текст чорний **`#000000`**.
- Шапка таблиці: світло-блакитна заливка **`#D9E1F2`**, жирний, `horizontal: 'center'`, `vertical: 'center'`, `wrapText: true`.
- Підвал підсумків: світло-сіра заливка **`#F2F2F2`**, верхня межа `thin`, нижня межа **`double`**, формули `=SUM(...)` замість захардкоджених сум.
- Якщо в таблиці з `autofilter` не можна робити об'єднання рядків по ПІБ — чергувати фон по групах (`#FFFFFF` / `#F7F9FC`) і ставити `top: { style: 'medium' }` на першому рядку кожного наступного військовослужбовця.

### Критичні пастки `xlsx-js-style 1.2.0-beta` (`v8/xlsx.js`)
1. **Ігнорування `!freeze` / `!views`:** бібліотека `v8/xlsx.js` НЕ записує закріплення областей в XML.
   - **Рішення:** формувати байти через `XLSX.write(wb, { type: 'array', bookType: 'xlsx' })` і через `JSZip` замінювати `<sheetViews>...</sheetViews>` у `xl/worksheets/sheetN.xml` на `<pane ySplit="N" topLeftCell="A{N+1}" activePane="bottomLeft" state="frozen"/>`.
2. **Обрізання шапки стрілкою автофільтра (`autoFilter`):** стрілка справа забирає ~`2.5–3 wch` ширини колонки.
   - **Рішення:** для вузьких числових/статусних колонок ставити явний перенос `\n` у назві (`Безперервно,\nдіб`, `Всього в базі,\nдіб`), висоту шапки **`34pt`** та ширину з запасом (`wch >= 18` для багатослівних заголовків, `wch >= 32` для ПІБ у bold).
3. **Об'єднані клітинки (`!merges`):**
   - Текст або формулу класти **виключно в верхню ліву клітинку** діапазону `s: { r, c }` — у будь-якій іншій клітинці merge значення ігнорується при відкритті.
   - При застосуванні `styleExcelRange` стилізувати всі клітинки діапазону merge, щоб рамки та заливка не переривались.
4. **Діапазон дат у шапці вибірки:** рахувати `effMin`/`effMax` суто по фактичних періодах експортованих записів, а не брати `globalMinDateStr`/`globalMaxDateStr`, які захардкоджують межі всієї бази.

## 2. Excel у Python (`openpyxl`) — зведення та аудит

### Пастки читання та запису
1. **Два проходи читання моделей:**
   - `openpyxl.load_workbook(path, data_only=True)` повертає кешовані обчислені значення, але **знищує формули**.
   - `load_workbook(path, data_only=False)` повертає формули (`=SUM(...)`), але без значень.
   - **НІКОЛИ** не зберігати файл, відкритий з `data_only=True`, поверх оригіналу — це назавжди зітре формули.
2. **Кешовані значення формул:** файли, щойно створені через `openpyxl`, мають у формулах кеш `None`, доки Excel їх не відкриє й не перерахує.
3. **Об'єднані клітинки:** при записі у вже об'єднану область звертатися тільки до верхньої лівої клітинки (інші є `MergedCell` і лише для читання).
4. **Сумісність формул:**
   - Використовувати класичні формули (`SUM`, `SUMIFS`, `IFERROR`, `INDEX/MATCH`, `SUMPRODUCT`).
   - Уникати `XLOOKUP`, `XMATCH`, `FILTER`, `UNIQUE`, `SORT` — при записі через `openpyxl` без spill-метаданих вони ламаються або дають `#NAME?` в старіших версіях Excel / LibreOffice.
   - Назви аркушів із пробілами в формулах брати в одинарні лапки: `='Зведений табель'!$D$2`.
5. **Обов'язковий аудит після генерації:** перевіряти згенерований `.xlsx` скриптом на `wb.sheetnames`, `ws.freeze_panes`, `ws.auto_filter.ref`, формули, ширини колонок та висоти рядків.

## 3. Word-документи (`.docx` — `v8/docx.js` та `python-docx`)

### Пастки створення в `v8/docx.js` (`docx-js`)
- **Таблиці — подвійна ширина в `DXA`:** задавати `columnWidths` на `Table` **І** `width` на кожній `TableCell`, обидва в `WidthType.DXA` (`1440 DXA = 1"`). Сума `columnWidths` має дорівнювати ширині таблиці (`PERCENTAGE` часто ламається при імпорті/перегляді).
- **Заливка комірок:** використовувати `ShadingType.CLEAR`, **ніколи `ShadingType.SOLID`** (інакше клітинка рендериться суцільно чорною).
- **Розриви рядків і сторінок:** не вставляти сирий `\n` всередину `TextRun` — використовувати окремі `Paragraph`. `PageBreak` завжди обгортати в `Paragraph`.
- **Списки:** використовувати `numbering` з `LevelFormat.BULLET` або нумерацією замість ручної вставки символів `•` з пробілами.
- **Орієнтація сторінки:** для альбомної передавати портретні розміри A4 + `orientation: PageOrientation.LANDSCAPE`.

### Пастки парсингу вхідних `.docx` (в браузері та `python-docx`)
1. **Роздроблені XML-теги (`<w:r>` runs):** Word часто розбиває одне прізвище або позицію на кілька окремих `<w:r>` (через перевірку орфографії, форматування чи історію правок). При пошуку й парсингу завжди збирати **повний текст абзацу/клітинки** (`p.text`), а не перебирати `run` поодинці.
2. **Об'єднані клітинки в `python-docx`:** у рядку `row.cells` об'єднані по горизонталі або вертикалі клітинки повертають той самий XML-елемент `_tc` кілька разів поспіль. Завжди дедуплікувати клітинки за `cell._tc` перед зчитуванням ПІБ, чисел або дат.
3. **Застарілі `.doc` файли:** бібліотеки `.docx` (`jszip`, `python-docx`, `mammoth`) НЕ читають бінарний формат Word 97–2003 (`.doc`) напряму — потрібно явно попереджати користувача або конвертувати їх у `.docx`.
