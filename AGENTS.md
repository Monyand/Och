# Rules

- **Do not modify files or execute modifications immediately on a user request.** When a request is made, first explain your proposed approach, describe the changes you can make (or provide examples/alternatives), and wait for the user's explicit command/approval to proceed before modifying any files or running commands.
- **Git Commits On Demand:** Do NOT automatically execute git commits after code changes. Execute `git add` and `git commit` ONLY when the user explicitly requests to commit (e.g. "закоміть", "комміть"). When requested, execute the commit immediately with a relevant Ukrainian commit message.
- **Mandatory Changelog & Version Sync (1 Commit = 1 Version):** During an active working session, accumulate code changes without bumping the version badge on every micro-edit. Consolidate all session changes into `CHANGELOG.md` and bump the UI version badge ONCE right before executing the user's explicit commit command ("закоміть").
- **No temporary scripts in workspace:** All temporary helper scripts, patch tools, and test scripts must be placed in the isolated artifact scratch directory or deleted immediately after execution to keep the workspace completely clean.
- **Mandatory Typography Standard (Inter Font):** For all existing, modified, and newly created HTML applications in this workspace, ALWAYS use the **Inter** font family (`font-family: 'Inter', sans-serif;` with Google Fonts `https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600;700;800&display=swap`) for all UI text, and **JetBrains Mono** for monospace/code/filenames/ammo indexes. Browser default fonts (Times, Arial, system-ui without Inter) are strictly prohibited.
- **Rock-Solid Layouts & Popovers on Zoom:** Toolbars with filters and counters must be organized in stable multi-row layouts (Row 1: filters & search; Row 2: full-width summary stats & actions) to prevent layout shifts at high browser zoom levels. Dropdowns and popovers in the right half of the screen must ALWAYS use `right-0` (expanding inwards) to prevent horizontal viewport clipping. Modal windows must have a high stacking context (`z-[200]` / `z-[210]`).
- **HUB & Interactive Version Badge Sync:** Every application in the suite must have a clickable/interactive version badge (e.g. `⚡ v3.4.0`) in its header that opens an in-app Changelog modal. When updating an application, its corresponding card in **HUB (`index.html`)** must be kept 100% in sync with version, release date, and tags.
